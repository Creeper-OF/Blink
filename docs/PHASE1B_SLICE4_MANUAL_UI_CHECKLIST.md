## 导航与键盘作用域

- [ ] Ctrl+L 聚焦地址栏并选中路径；地址栏内 Ctrl+A 只选择文本。
- [ ] 地址栏 Enter 只提交一次导航，不同时激活文件列表。
- [ ] This PC 中 Enter 进入当前焦点/选中的位置；目录中 Enter 和双击都走既有导航路径。
- [ ] F5 刷新当前标签；Alt+Left、Alt+Right、Alt+Up 与 Back、Forward、Up 具有同样的历史语义。
- [ ] 文件列表 Ctrl+A 选择当前已完成呈现的目录内全部有效行；硬链接的两个名称都可独立选择。
- [ ] 两个标签分别导航、全选、排序、切换，确认选择和历史不串台；已有 Ctrl+T/W 每次只执行一次。
- [ ] 10k/50k fixture 中检查 Ctrl+A 后的响应性与 selected count；不预填耗时或假定无停顿。

## 文件关联打开

仅使用项目 `.build` 中本轮创建的安全文件和目录，保留真实用户文件。

- [ ] 双击安全文本/图片文件，通过当前用户的默认应用打开；状态只表示已提交打开请求。
- [ ] 在同一文件上按 Enter，实际打开对象正确；Ctrl/Shift 多选后 Enter 激活有选择的焦点行，或首个选中行。本 Slice 不实现批量文件打开。
- [ ] 中文文件名与中文路径正常；另记录长路径的实际结果或可解释失败。
- [ ] 未关联的安全扩展名给出明确错误；不显示成功、不使用默认打开方式回退来掩盖失败。
- [ ] 枚举后删除文件，或将原文件移到另一个名称后在旧名称创建替代文件，再尝试打开旧行：报告失败/对象变化，不能打开替代文件。
- [ ] 两个真实硬链接分别打开；删除一个 link 后，该旧行失败，其余 link 刷新后仍可使用。

## 生命周期与回归

- [ ] 文件身份检查或系统打开请求进行时，窗口仍响应拖动、resize 和导航。
- [ ] 请求后立即导航到另一目录：未派发的旧请求取消，旧结果不能覆盖新目录状态。
- [ ] 请求后切换标签：结果属于原标签；当前标签的路径、状态和选择不被旧回调覆盖。
- [ ] 请求后关闭标签或窗口：关闭不等待外部应用，不能出现 stale UI 回调、崩溃或不必要残留进程。
- [ ] Windows 已接受的打开请求可能继续启动目标应用；关闭标签不会撤回已提交的操作。
- [ ] `Blink.FileActivationHost.exe` 正常派发后退出；取消或关闭时已拥有的 helper 被清理，目标应用继续运行。记录派发超时/失败的可解释结果；超时后先检查目标应用，避免误重复启动。
- [ ] This PC、导航树首次展开、重复折叠展开、统一滚动、标签关闭及 hard-link selection 的既有验收行为保持正常。
