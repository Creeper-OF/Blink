# 工作台分类与清理规则

本规则落实用户要求：旧构建、无用缓存和临时文件及时处理，不能只生成不清理。适用于每批功能、构建、测试和审计收尾。

## 固定归属

| 内容 | 位置与保留方式 |
| --- | --- |
| 源码、测试、文档、项目脚本 | `src/`、`tests/`、`docs/`、`scripts/`；不作为垃圾清理 |
| 当前工程引用的依赖 | `.nuget/packages/`；保留有效版本，不能按日期或体积直接删包内文件 |
| 当前 Debug/Release 运行文件、匹配符号和增量缓存 | 工程现有 `src/Blink/x64/`、`x64/` 及各项目配置目录；每配置保留一份有效缓存 |
| 本批候选、服务候选、日志、临时验证 | `.build/<功能主题>/{runtime,service-build,integration}/`；最多保留本批一个必要候选 |
| 清理与审计事实 | `.build/maintenance/`，本次审计在 `code-audit/`；最终结论归 `docs/` |
| 成功源码恢复点 | 已校验 CRC/逐项 SHA 的最近两个恢复包；未完成验证的候选不冒充成功版本 |
| 正式索引、设置与用户数据 | `.blink-data/` 及用户资料位置；不清理 |
| 开发工具 | 现有 `D:\DEV\` 分类目录；不在主目录、工作区根层或项目根层散放安装包/工具 |

## 每轮收尾必须做

1. 先确认构建、测试和调试进程已经退出；核对路径归属及是否仍被使用。在途目录不清。
2. 删除本轮已完成、身份与内容核对无误的自有夹具、临时编译目录和重复下载；异常或被修改的夹具保留并明确记录。
3. 候选发布且关键文件 SHA 一致后，删除重复候选运行文件。候选尚待验证时保留唯一必要版本，标记待验状态，不能作为“无用旧构建”删掉再重编。
4. 新成功恢复点校验完成后，淘汰超过最近两个的旧成功恢复点。失败重试不积累整套二进制、完整源码副本或压缩包。
5. 清理明确失效、未引用的旧配置/工具链缓存和旧依赖版本；保留当前构建仍可复用的缓存。大目录或时间较早不等于失效，不能每轮清空有效缓存导致再次全量编译。
6. 留简明清理记录：路径、归属理由、删除文件数、实际删除字节、保留项及未清理原因；区分累计删除量与磁盘净变化。
7. 检查临时进程、构建 junction 和残留目录，更新本项目进度及工作区资产索引。

不删除源码、用户数据、有效配置、密钥、唯一副本、正在使用的工具或其它任务文件；不借清理进行无关重构。公开仓库只同步源码和文档，不上传 `.build`、索引、依赖缓存、调试符号或本机数据。

现有 `clean-local.ps1 -WhatIf` 可预览下载/临时缓存；它不替代本批候选、夹具与恢复点的生命周期检查。不要把 `-IncludePackages` 当日常清理选项。
