## 来源与失效

- [ ] 单目录Ctrl+C、右键复制和粘贴进入目录复制；普通文件多选仍进入原文件队列。文件混目录、多目录、重复目录整包明确拒绝，不能只操作前缀。
- [ ] 外部资源管理器的标准Unicode CF_HDROP/COPY目录可以在Blink粘贴；Blink目录COPY可以被外部目标识别。Blink不执行外部目标的实际复制，不发布Cut或删除源。
- [ ] 内部目录COPY后源被同名替换，粘贴明确身份失败且目标零写；不能丢弃最初typed source/parent ID并把替换对象当外部新来源接受。
- [ ] 剪贴板sequence或有序路径被其它程序改写后，不继续套用旧来源；长路径归一化不能绕开原身份保护。
- [ ] 用后续可控准备延迟夹具分别验证文件和目录：A→B、A→B→A、切换标签再返回、进入搜索再返回后，原准备结果和对话continuation不能迟到提交。核对generation失效，而非只比较当前位置相同。
- [ ] 准备阶段取消、准备完成到UI提交之间取消、关闭窗口后回调，均不得启动新复制；窗口不等待worker。导航只使旧提交失效，不能重定向已执行操作。

## 真实结果、取消与重试

- [ ] 普通、空、嵌套Unicode/长路径目录复制正确，文件内容及已支持的附加数据流保留；源目录不变。状态区区分扫描、创建数量、已完成文件与当前文件字节。
- [ ] 当前文件变化后bytes可以归零，单个文件100%不表示整个目录已完成；completed进度也不提前开放新的mutation。
- [ ] 目的地为源自身/后代、root已存在、源身份变化和不支持的reparse/目录ADS等情况明确报告；不隐式Merge/Replace、跟随junction或失败后切换文件API。
- [ ] 已有root只提供新名称或取消；非法名称留在明确的重试流程。目录失败/取消后的名称重试确实重新复制目录，不能进入通用新建空目录。
- [ ] 创建空root后立即取消，及已有提交文件后取消，均呈现实际partial root、数量和失败位置；只刷新同目标父identity的相关标签，不能因通用partial_file_left=false漏刷。
- [ ] 另取名称重试成功后，之前的partial root及提示仍保留；没有自动续写、接管、删除或整树回滚。真实失败前缀与源/sentinel均独立检查。
- [ ] 最后真正提交后的晚取消保持成功；observer显示异常不能把已提交树说成未写入。失败结果不得伪装为成功或已回滚。

## 窗口与共享任务门禁

- [ ] 同名/失败对话只在真实native action退出后开放；终态已发布但action仍Started时，不能提交新文件或目录操作。
