# 搜索结果与 Windows 原生右键菜单

此记录描述原生承载基础；当前默认外观已更新为[Blink风格主菜单](SEARCH_THEMED_MENU_HANDOFF.md)，完整系统菜单从扩展入口保留。

本轮实现、双配置构建、普通回归、原生菜单与生产界面自动检查已完成。用户解锁并关闭旧窗口后，已将候选发布到默认启动目录，校验程序、资源和helper哈希，并打开新版供用户操作。人工体验验收保持独立。

## 使用方式

搜索结果支持鼠标右键、菜单键和 Shift+F10。使用 Windows 完整经典菜单，已注册的第三方 Shell 菜单扩展由系统提供，例如压缩软件的压缩/解压入口；不另做一套压缩软件适配，也不复刻 Win11 新式首层菜单外观。

菜单补充复制完整路径、复制所在目录路径、打开所在目录并定位、粘贴到所在目录。粘贴始终以该结果的父目录为目标，包括文件夹结果；菜单明确写出目标语义。空白处右键不借用上一次选中结果。

Ctrl+C/X/V、F2、Delete、Shift+Delete、Alt+Enter、Ctrl+Enter 分别对应复制、剪切、粘贴到所在目录、重命名、回收站删除、确认后永久删除、系统属性和定位；原有 Enter/双击打开继续可用。

## 实现与操作归属

- `SearchContextSelection`保存标签、已提交查询代次和精确结果链接；不从背后的普通目录选择借用文件。改高级搜索草稿不作废已显示结果，提交新查询、离开或切换标签会取消旧菜单。离开再返回也不能复活旧命令。
- `Blink.ShellMenuHost.exe`以普通用户的独立 STA 进程承载`IContextMenu`与第三方 DLL；主窗口仅等待一次选择。转发`IContextMenu2/3`绘制和级联消息，原生属性沿用 Windows 实现。
- Windows 标准打开、复制、剪切、重命名、删除和粘贴回到 Blink 现有入口。复制/剪切使用原标准 CF_HDROP 和身份缓存；复制路径使用 Unicode 文本。重命名、删除、粘贴先完成父目录浏览并选中精确结果，再进入既有队列或对话框；定位失败或被新导航取代则取消命令，不由后续刷新继续执行。
- 其它原生命令保留系统行为。选择前可以取消菜单，选择后不会因 Blink 关闭而强杀已启动的系统任务。异步调用使用 Shell 线程引用和 STA 消息循环保活，菜单自有引用在等待前释放。主窗口“已交给 Windows”仅表示已提交，不表示第三方操作已成功；调用失败由原生承载程序显示真实错误。
- 不增加管理员服务功能，不改变索引协议、存储格式、查询或文件操作队列，不安装压缩软件或注册扩展。

## 发布与续接

正常启动位置为`src/Blink/x64/Release/Blink.exe`。先搜索文件，再在搜索结果上右键，或使用菜单键/Shift+F10，即可打开完整系统菜单。此项新增作用于搜索结果。已验证的候选在发布和哈希确认后删除重复副本，保留当前Debug/Release、依赖缓存、真实索引以及最近两个源码恢复点。
