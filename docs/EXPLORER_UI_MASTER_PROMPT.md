# Blink × Windows 11 文件资源管理器：完整 UI、菜单与交互兼容任务书

> 用法：将本文件放入 Blink 仓库根目录，交给 Codex / 代码 Agent 阅读并执行。它是**产品规范 + 源码审计指令 + 分阶段开发任务 + 验收标准**，不是让模型在一轮里重写整个项目。

## 0. 你的身份与最终目标

你是一位熟悉 Windows 11 Explorer、Windows Shell、Win32、COM、C++20、C++/WinRT、WinUI 3、Windows App SDK、UI Automation、Windows 文件操作语义的高级桌面应用工程师，同时负责交互设计与 QA。

你需要在已有开源项目 **Blink** 中，建立一套**以 Windows 11 稳定版文件资源管理器为行为基准**的完整 UI 与交互兼容方案，并分阶段落地。目的不是复制 Explorer 的内部代码、强行替换 Explorer，也不是制造仅能截图的仿制界面，而是让 Windows 用户使用 Blink 时，沿用已有的操作习惯、快捷键、上下文菜单、拖放和文件操作预期。视觉采用 Windows 11 Fluent / WinUI 3 原生风格，允许适度的 Blink 品牌个性，但不得牺牲操作一致性。

**基准环境**：Windows 11 24H2 x64，后续 Windows 11 稳定更新通过运行时能力检测适配；Windows 版本、地区、账户、文件类型和第三方扩展会使 Explorer 菜单不同。凡不是跨版本固定功能的项目，都必须标记“条件显示／版本依赖／系统托管”，不可假定全球所有 Explorer 界面一模一样。

**功能范围说明**：“覆盖 Explorer 的所有 UI 与菜单”表示建立**完整功能清单、交互规范、差异台账、落地计划和验证矩阵**。不代表在一个提交中实现整个 Windows Shell Namespace。系统动态菜单由 Shell API 获取；尚未支持的特殊对象或操作必须明确 Deferred/Unsupported，绝不伪装成已实现。

## 1. 读取仓库、建立事实，禁止盲目重构

先阅读实际仓库，再作任何设计决定：

- `README.md`、`PROGRESS.md`、`DECISIONS.md`、`ARCHITECTURE.md`、`docs/PRODUCT_SCOPE.md`、`PHASE1_PLAN.md`，以及最新 handoff；历史 `Blink_PROGRESS.md` 可能过时，以最新记录和实际源码为准。
- `src/Blink/src/main.cpp`、`App.xaml`/界面资源、`TabState`、`TabWindowState`、`NavigationModel`、`NavigationTree`、`FolderViewPresentation`、`SearchPresentation`、`ContextMenuAppearance`、`ShellContextMenuController`、`FileOperationCoordinator`、`ClipboardFileTransfer`、`FileDragDropController` 及其实际对应源码。
- `Blink.Core`、`Blink.Index*`、`Blink.FileActivationHost`、`Blink.ShellMenuHost`、`Blink.Provider*`、`tests`、`build.ps1`、`Strings/zh-CN` 与 `Strings/en-US`。

准确区分 **已实现 / 已实现但待手工验收 / 部分实现 / 计划中 / 不在产品范围 / 系统能力依赖**。禁止因为文档标题老旧就否认真实代码，也禁止因为有原型就宣称功能已完成。

保留既有架构原则：

1. UI 控件仅用于展示，不能成为导航、标签、选择、任务和路径身份的唯一真相源；继续复用现有 app-private `Location`、`TabState`、`TabWindowState`、`FileIdentity` 与文件操作协调器。
2. 不把 Blink 改造成 Shell Namespace 全量替代品，不用伪造的绝对路径表示“此电脑”“搜索结果”等虚拟位置。
3. 不删除已完成的 MFT/USN 索引、索引服务、已有 IPC 边界、文件操作正确性和进程隔离。`IndexService` 不得新增任意高权限复制、删除、重命名后门。
4. 第三方 Shell 扩展不直接加载到 Blink 主 UI 进程。优先复用已存在的 `Blink.ShellMenuHost`，必要时扩展其安全、超时与兼容能力。
5. 禁止一次性重写 `main.cpp` 或换一套 MVVM/前端框架；新增界面职责应按已有代码风格渐进抽离，减少耦合和重复状态。
6. 不改变系统默认资源管理器、Win+E 关联、注册表 Shell handler、文件关联、管理员服务或安装配置，除非有独立任务和用户明确同意。
7. 所有影响用户真实数据的测试仅针对自动创建、明确隔离的临时目录；默认非管理员执行；不可扫描、清空、修改用户真实目录。

**先完成只读审计，再提交第一批小步代码更改。** 不得跳过审计直接生成整套新界面。

## 2. UI 总体信息架构：对齐 Explorer 窗口骨架

请先制作一份完整、可审查的“窗口结构图 / 控件树 / 状态和命令绑定图”，覆盖：

### 2.1 窗口与标题栏
- Windows 11 风格标题栏：应用图标、TabView、当前标签标题、标签关闭按钮、新建标签、最小化、最大化/还原、关闭。
- 系统窗口拖动、双击标题栏最大化/还原、窗口边缘调整大小、Snap Layout、正确的窗口消息/非客户区与命中测试；不能用自绘控件破坏系统系统按钮。
- Mica、浅色/深色、激活/非激活状态、系统强调色及高对比度模式；不应出现标题栏与内容区主题断裂。
- DPI 从 100% 至 200% 变化、多显示器移动、文本缩放、窄窗口、小分辨率布局；命令栏在不足宽度时合理溢出，而不是裁剪文字。
- 标签标题及时同步目录名，显示真实图标或合理系统图标；异步导航不能使已关闭标签重新出现。

### 2.2 标签页
- 新建、切换、关闭、拖动重排、关闭前后选中关系、标签溢出/滚动、标签悬停与焦点。
- Ctrl+T、Ctrl+W、Ctrl+Tab、Ctrl+Shift+Tab 等系统约定；若支持中键关闭、右键标签菜单，则按照目标系统实测行为实现。
- 标签右键菜单逐项核对：关闭、关闭其他、关闭右侧等；仅在该目标版本存在且 Blink 真正支持时启用。新窗口、拆分标签、拖出窗口等属于能力扩展，不得用空菜单占位。
- 每个标签独立的路径、历史、排序、视图、选中项、滚动位置、搜索上下文和异步取消状态；标签间不得串数据。

### 2.3 导航栏与地址栏
- 后退、前进、上一级、刷新；可用/禁用状态与历史栈严格一致；鼠标前进后退侧键可纳入兼容测试。
- 面包屑地址栏：层级段点击、下级目录菜单、路径过长收缩、从显示模式切换到文本编辑、全选/复制路径、手工键入盘符路径、UNC 路径、粘贴后 Enter 导航、Esc 恢复。
- Alt+D、Ctrl+L、F4 等地址栏快捷键，以目标 Windows 11 实机行为为准；输入法和 Unicode 路径正常；非法路径、不存在目录、拒绝访问应提供正确反馈。
- 地址栏历史/候选建议可独立标注优先级。不得把“此电脑”当成 C:\ 目录，不得在 URL、UNC 与本地路径之间盲目互转。
- 搜索框位于导航栏右侧，提示文字随当前目录改变；输入、清除、取消、焦点与搜索范围都受每标签状态管理。

### 2.4 顶部命令栏（Command Bar）
- 依据选中对象及位置展示：**新建 ▾、剪切、复制、粘贴、重命名、共享、删除、排序 ▾、查看 ▾、… 更多**。
- 上下文动作：图片旋转、设置背景、压缩包“全部提取”、驱动器相关操作等，仅在适用对象和系统能力存在时出现。
- 每项必须有正常、悬停、按下、获得焦点、禁用、加载中的反馈；Tooltip、快捷键提示、AutomationName、图标、分隔线与菜单箭头符合 Fluent 规范。
- 没有选中对象时，剪切/复制/重命名/删除应禁用或按 Explorer 语义隐藏；多选与混合选中要正确地计算可用操作，不能仅检测是否有首个条目。
- 从本地目录切换到“此电脑”、搜索结果、远程位置时，命令项与执行目标同步更新，不出现陈旧菜单或旧路径。

### 2.5 左侧导航窗格
- 主区域按 Explorer 的基本认知组织：主页/快速访问、已固定目录、桌面、下载、文档、图片、音乐、视频、此电脑、各本地/可移动驱动器、网络等。
- 主页、图库、OneDrive、回收站、库、网络映射盘、Shell 特殊文件夹等：必须判断 Blink 当前的真实能力和系统环境；可以提供明确的支持入口或原生系统跳转，但不可伪造已接入的数据或“假文件夹”。
- 常用位置固定/取消固定、折叠/展开、Lazy Load 子目录、滚动、焦点、选中高亮、活动标签和左树同步；外部设备移除后正确失效。
- 导航树单一滚动容器；避免嵌套滚动条、反复展开重复节点和重新遍历整个磁盘。
- 空白处、快捷访问项、普通目录、驱动器、网络位置具有不同的右键菜单；不得将文件菜单硬套到全部导航节点。

### 2.6 主文件区域
- 对照 Explorer 设计并逐项登记：超大/大/中/小图标、列表、详细信息、平铺、内容视图；Blink 已有的 Details/List/Grid 可保留并逐步补齐。不可把未来视图显示成已可用。
- 文件/文件夹图标来自适当的系统来源；显示扩展名、隐藏项、受保护系统文件、隐藏属性淡化、快捷方式箭头、可选的同步状态覆盖标记（如 OneDrive）均应与实际系统事实一致。
- 详细信息列：名称、修改日期、类型、大小，以及 Explorer 按文件类型支持的动态属性列；列头排序、升降序、列宽拖动、重排、显示/隐藏、适当的右键列头菜单。
- 文件夹优先与按名称/类型/大小/修改日期等排序策略，需区分 Explorer 实际规则与 Blink 用户设置；支持分组（无、名称、类型、日期、大小等可用项）时不能与排序混淆。
- 单击选择/双击打开、Ctrl 单选切换、Shift 范围选、Ctrl+A 全选、空白点击取消、框选、键盘移动、Home/End、PageUp/PageDown、滚动保留、滚动到已选行、鼠标悬停、项目复选框（若启用）。
- 重命名模式：F2 默认只选中主文件名、不选中扩展名；Enter 提交、Esc 取消、非法字符与名称冲突展示、IME 候选窗、超长文件名和焦点变化；不可误将编辑文本的 Delete/Ctrl+A 传给文件操作全局快捷键。
- 大目录必须采用现有异步/增量呈现，不在 UI 线程读取所有元数据和缩略图；延迟结果必须受 TabId、generation 和窗口生命周期约束。
- 空目录、读取中、无权限、断开连接、目录已删除、无搜索结果、索引服务离线、文件路径失效，各自有清晰状态，不得显示上一个目录的结果冒充当前目录。

### 2.7 详情面板、预览面板、状态栏
- “查看 > 显示”按系统位置提供导航窗格、预览窗格、详细信息窗格、项目复选框、文件扩展名、隐藏项目等开关。
- 详情面板按零选中、单选、多选分别显示有效属性（预览图/图标、名称、类型、位置、大小、时间、图片尺寸等），不阻塞主列表。
- 预览面板必须处理未实现格式、没有预览处理程序、解码超时、恶意/损坏文件、文件消失；第三方预览 Handler 不在 UI 主进程内无限等待。未实现前隐藏可操作入口或明确标为未提供。
- 状态栏展示当前文件夹项目数、选中数、选中项大小（可获得时）、加载/后台操作提示及合适的视图切换入口；与当前活动标签一致。

## 3. 顶部下拉菜单与二、三级子菜单：必须列全并验证

为下面每个菜单建立 **Menu ID / 中文 / 英文 / 路径 / 对象适用性 / 启用条件 / 预期操作 / 系统接口 / 现有实现 / 测试编号**。在目标系统上比对具体文字、顺序、分隔线、图标和键盘导航。下列是**必须覆盖的类别**，不是忽略系统差异的硬编码最终清单。

### 3.1 「新建」及其子菜单
- 新建文件夹、快捷方式；从系统 `ShellNew` 注册/关联提供适用的文件类型模板，如文本文件等。
- 系统、Office、压缩软件等应用可能扩充“新建”菜单；通过受控 Shell 机制动态获取，绝不手写固定的 Word/Excel/ZIP 项目假装所有电脑都有。
- 新建后遵循 Explorer 的焦点、重命名、排序及选择逻辑；重名、无权限、只读位置等错误要有反馈。

### 3.2 「排序」子菜单
- 名称、修改日期、类型、大小及当前视图支持的其他属性；升序/降序；当前项的单选/勾选标识。
- 文件夹、搜索结果、此电脑等不同位置可用排序项不同；不提供无效大小排序、不得静默修改默认排序模式。

### 3.3 「分组依据」子菜单
- 无、名称、日期、类型、大小及当前列允许的属性；组标题、展开/折叠、升降序（以 Explorer 实测为准）。
- 分组不是排序。未实现时列为缺口而非在 UI 上放装饰性菜单项。

### 3.4 「查看」子菜单
- 超大图标、大图标、中等图标、小图标、列表、详细信息、平铺、内容；紧凑视图（若适用）。
- 「显示」三级菜单：导航窗格、预览窗格、详细信息窗格、项目复选框、文件扩展名、隐藏的项目；如某些选项在不同版本放在其他位置，以实机为准。
- 每个菜单项正确处理勾选、互斥、快捷键、持久化、重新打开文件夹后的状态恢复。

### 3.5 「… 更多」菜单
- 全选、全部取消、反向选择、属性、选项/文件夹选项、打开设置等系统常见命令；版本/当前对象相关的提取、压缩、刻录、固定、共享或其他命令在相应上下文出现。
- 文件夹选项（如默认打开位置、单击/双击、显示隐藏扩展名、隐私相关设置）只对 Blink 自身承诺支持的设置提供有效入口；系统全局设置应调用对应 Windows 设置界面，不可伪装成 Blink 已接管。
- 菜单与命令栏重复的操作必须共享唯一 Command/Action 入口，不能维护两套行为。

## 4. 右键菜单：完整场景矩阵与动态 Shell 兼容

**第一原则：菜单内容由上下文决定。** 至少穷举并区分以下 12 个场景，必要时按文件类型细分：

1. 普通文件单选（区分 exe、普通文档、图片、媒体、脚本、快捷方式等）。
2. 普通文件夹单选。
3. 多个文件、多文件夹、文件+文件夹混合选择。
4. 文件列表真正空白处。
5. 搜索结果中的文件/文件夹；执行对象是原始真实项而不是搜索结果缓存文本。
6. 左侧导航区的已固定文件夹/快速访问项。
7. 左侧导航区的普通可展开目录。
8. “此电脑”的本地磁盘根、可移动磁盘、光驱（如果存在）、网络映射驱动器。
9. “此电脑”页面背景以及虚拟位置内容。
10. 回收站内容与回收站根（仅在真正支持时）。
11. UNC/SMB 网络共享与未来 Provider 远端对象。
12. 标签栏标签、地址栏面包屑与编辑框、搜索框、详细信息列头等特殊上下文。

### 4.1 Windows 11 现代右键菜单
- 顶部常用命令区：剪切、复制、粘贴（适用时）、重命名、共享、删除；图标位置、禁用、提示和分割与目标版本 Explorer 对照。
- 具体条目常见命令：打开、打开方式、编辑/打印（文件关联支持时）、以管理员身份运行（适合的程序/系统处理时）、固定到快速访问（目录）、复制为路径、属性、压缩为 ZIP/其他系统支持格式、全部提取（归档文件）、发送到、创建快捷方式，以及按目标系统真实支持的其他项。
- 仅文件具有有效关联时才显示打开方式/编辑/打印；仅目录提供固定到快速访问、在新标签页/新窗口打开等适用项；快捷方式提供打开目标位置/适当属性；图片专属操作仅对有效图像启用。
- 文件夹背景的常见命令：查看、排序方式、分组依据、刷新、粘贴/粘贴快捷方式、新建、在终端中打开、属性或自定义相关命令（严格按该位置/系统验证）。桌面背景才有的“显示设置/个性化”不得无条件放进普通文件夹背景菜单。
- 针对盘符和设备：打开、在新标签中打开、属性、弹出/格式化/管理等**仅在设备类型适用且经过用户确认**时显示；不能把“格式化”“清空回收站”放到普通目录菜单。

### 4.2 “显示更多选项”与旧式系统菜单
- 保留独立的“显示更多选项”入口，支持适用的 **`IContextMenu` / `IContextMenu2` / `IContextMenu3`** 旧式菜单及其子菜单、图标、分隔、状态、owner-draw/窗口消息、InvokeCommand、取消操作；需核对对应接口在当前项目中的真实实现。
- 对 Windows 11 新式扩展使用系统 `IExplorerCommand` / Shell 注册信息按可实现能力对接；不能承诺仅凭枚举传统 `IContextMenu` 就能复刻所有现代 Explorer 菜单。
- 动态系统扩展（如 Bandizip、7-Zip、VS Code、Git、云盘等）是否出现取决于用户的实际安装、注册、上下文和系统版本。**没有安装就不显示，不能硬编码第三方名称。**
- 上层界面由 Blink 自己维护已实现的核心命令；“更多系统选项”调用原生系统 Shell 能力，不能做一个视觉仿制菜单然后只调用 `ShellExecute` 猜测行为。
- 第三方 Shell DLL 不进入 `Blink.exe`。复用 `Blink.ShellMenuHost` 普通用户进程承载，具有超时、崩溃隔离、句柄/消息生命周期管理和正确的错误反馈；不静默提权或禁用系统安全机制。
- 单选与多选菜单需真实传入选中集合；使用共同可执行的命令，不对混合选中强行展示单文件命令。
- 菜单启动时被选文件可能已经删除/重命名，操作前校验目标状态；失败只影响该操作，不影响整个 UI。

### 4.3 下级菜单与状态
- 右键菜单中逐项审计所有可能的二、三级菜单，包括“打开方式 >”“发送到 >”“新建 >”“排序方式 >”“分组依据 >”“查看 >”“共享 >”“压缩到 >”等，具体以系统 Shell 返回与目标版本截图为准。
- 键盘 Shift+F10 调起选中项菜单；箭头方向键、Enter、Esc、鼠标移入/移出子菜单、左右边界反向展开、高 DPI 多显示器位置，以及 Alt 辅助键/无障碍读屏行为可靠。
- 文字菜单不能把显示名称当作 Command ID；支持 zh-CN/en-US 资源，切换语言后命令仍指向相同动作。
- 菜单创建不得同步扫描大量文件、访问网络、运行第三方耗时代码，从而冻结 UI。

## 5. 属性窗口、文件夹选项和系统对话框

### 5.1 属性
- 文件、目录、驱动器、快捷方式、多选对象的属性入口要遵守系统差异。
- 基本属性：名称、类型、打开方式、路径、大小/占用空间、创建/修改/访问时间、只读/隐藏、文件夹统计等；能否编辑按权限和对象类型决定。
- Windows 原生“常规 / 安全 / 详细信息 / 以前的版本 / 自定义 / 共享”等页签不是对所有对象固定出现；优先以**调用系统属性页**保证与 ACL、扩展页和文件关联的兼容，Blink 自定义简洁详情面板作为补充。调用失败时明确给出错误。
- 修改只读/隐藏/权限/共享前验证权限并展示确认，绝不虚拟更改 UI 而不写入真实状态。

### 5.2 文件操作对话框
- 复制、移动、重命名、新建、删除、永久删除、文件夹合并和冲突处理：按钮、默认焦点、Esc、关闭、错误反馈和确认提示符合 Explorer 习惯。
- 文件与文件冲突：替换、跳过、保留两个、取消；文件夹与现有文件夹冲突：合并、跳过、保留两个、取消。不得先删除目标目录再处理合并。
- 传输状态：源、目标、进度（已知总量时）、速度、剩余量（仅可信时）、暂停（仅有真实支持）、取消、正在处理的文件、完成/部分完成/失败的区别；失败项允许解释/重试时要确保已成功部分不被重复覆盖。
- 复制/移动进度中的用户确认不阻塞 UI 消息循环；禁用危险重复提交；关闭应用或取消时保持已提交数据的正确性。
- 删除优先系统回收站，永久删除明确确认；不能因回收站 API 失败**静默降级为永久删除**。
- Win32 错误（无权限、空间不足、文件被占用、路径过长、非法名称、源消失、跨卷失败、符号链接/重解析点限制等）应以用户可理解文案呈现，同时保留可诊断原始错误码。

### 5.3 其他常见对话框
- “打开方式”、共享、文件关联、终端打开、选择文件夹、系统文件属性、确认覆盖、网络凭据、UAC：优先系统原生流程和正确的 Win32/COM API；不要伪造系统对话框。
- 文件夹选项、查看选项、关于/设置、默认管理器接管选项分别明确哪些属于 Blink 私有设置、哪些属于 Windows 全局设置。
- 进度、空状态、错误、权限不足、设备移除、不可用索引服务、远端未连接状态都必须有明确 UI；支持“取消/重试/查看详细信息”的准确能力判定。

## 6. 输入、快捷键与操作逻辑：用 Explorer 行为作验收基准

建立完整快捷键表并注明适用焦点与上下文；以下至少涵盖：

- **导航**：Alt+←/→/↑、Alt+D、Ctrl+L、F4、F5、F6、Shift+F6、F3、Tab/Shift+Tab、Enter、Esc。
- **标签**：Ctrl+T、Ctrl+W、Ctrl+Tab、Ctrl+Shift+Tab，以及经过实机确认的中键/标签右键行为。
- **选中与编辑**：Ctrl+A、Ctrl+单击、Shift+单击、Shift+方向键、Home/End、PageUp/PageDown、F2、Ctrl+C/X/V、Ctrl+Shift+N、Delete、Shift+Delete、Shift+F10。
- **撤销/重做**：Ctrl+Z、Ctrl+Y 等；若 Blink 还没有安全的撤销日志，不得绑定成虚假的可用命令。输入框编辑撤销应与文件操作撤销严格区分。
- **视图**：Ctrl+Shift+数字等视图切换，仅在实际实现且目标系统匹配后开放；F11 及缩放相关按键以目标 Explorer 版本和焦点核对。
- **打开行为**：普通双击文件按 Windows 文件关联打开，双击目录导航；Ctrl/Shift/中键修饰符仅根据实机/官方行为定义，不允许自创“Ctrl+双击一定开新窗口”的假定。
- **拖放**：同卷默认移动、跨卷默认复制（按系统典型路径规则），Ctrl 强制复制、Shift 强制移动、Alt 或系统支持的修饰组合创建快捷方式；鼠标右键拖放菜单，拖放提示与最终动作准确；剪贴板和拖放支持 Explorer 互操作。
- **剪贴板协议**：基础 CF_HDROP、OLE IDataObject、Preferred/Performed DropEffect、剪切视觉反馈；虚拟文件/第三方拖放需按 FileDescriptor/FileContents 的实际支持能力另列，不可宣称全面支持。
- **文本输入优先级**：地址栏、搜索框、重命名输入框、对话框的快捷键需优先服务文本编辑，不能把 Delete、Ctrl+A、Ctrl+V 误转成对文件操作。
- **多选右键**：右击已选集合内的项目保持集合；右击未选中项目按 Explorer 规则调整选择；空白右击按背景菜单语义执行。操作对象取自权威 selection model，而非虚拟列表的可见行。

## 7. 文件系统和 Shell 正确性

- 本地路径、盘根、UNC、可移动卷、隐藏项、只读项、系统项目、快捷方式、硬链接、符号链接、junction、重解析点；在每种状态下对“打开/重命名/复制/移动/删除/属性”建立能力边界。
- 文件名大小写、长路径、Unicode/emoji、结尾点/空格、扩展名隐藏、不同编码、同名冲突、文件占用、共享冲突、只读、ACL、ADS、文件时间戳和刷新行为。
- 稳定文件身份仍是 Volume identity + File ID；多硬链接名称必须有额外的行/链接标识，不能只凭文件名或 UI 列号执行操作。
- `ShellExecuteEx`、文件关联、注册的动词、协议/压缩/快捷方式行为正确；不随意硬编码可执行文件打开方式。
- 对特殊 Shell Namespace（库、回收站虚拟页、手机 MTP、云盘占位符、控制面板、搜索虚拟容器、网络发现）：分别判断“原生管理 / 有限操作 / 系统跳转 / 暂缓”；不要将不能当真实普通文件目录管理的对象冒充普通本地路径。
- Blink 搜索继续使用现有索引状态机；索引不可用时必须告知，不能偷偷执行高负载全盘 DFS 搜索。按当前标签范围搜索要正确标明查询范围。
- SFTP/WebDAV 等未来 Provider 不需要强行伪装 Windows Shell COM 项目；统一 Blink 的视觉/交互，但遵守各协议真实语义（权限、可取消、断线、上传状态），不执行本地文件系统特有的操作。

## 8. UI 视觉规范：原生、克制、行为比特效重要

- Fluent Design / Windows 11 风格，WinUI 3 首选标准控件和主题资源，合理使用 `Mica` / `Acrylic`；优先系统 Segoe UI Variable、系统尺寸/颜色/圆角/阴影/动效规范，不使用未经授权的系统私有素材。
- 布局层次优先保留 Explorer 的“标签 → 导航/地址 → 命令 → 导航树与内容 → 状态”的认知结构。品牌差异用图标、轻度配色和可选紧凑模式，不改变常用动作的位置与意义。
- 菜单密度、点击热区、上下文菜单的位置与展开方向、Tooltip、禁用态、聚焦框、加载骨架和错误态必须统一；窄窗口优先采用溢出菜单。
- 浅色、深色、高对比度、系统缩放 100/125/150/200%、文字放大、减少动画、触摸热区、鼠标和触控板均要验证。
- UI Automation：控件名称/角色/状态/键盘导航、焦点顺序、列表选择、TabView、TreeView、菜单和对话框可被屏幕阅读器理解。不能为了自绘美观破坏无障碍功能。
- 不强制动画、不靠频繁 UI thread repaint 维持“高级感”；闲置时避免持续消耗 CPU。实现真实截屏对照，而非仅凭提示词推断视觉相似。

## 9. 菜单与功能台账：所有条目都要能追踪

先建立 `docs/EXPLORER_MENU_MATRIX.md`，每一条包含：

`场景 | 菜单路径(一级>二级>三级) | 中文文案 | 英文文案 | 图标 | 条件 | 命令ID | 实现方式(Blink/Shell/系统跳转) | 状态 | 证据 | 测试ID`

状态只能使用：`IMPLEMENTED_VERIFIED`、`IMPLEMENTED_NEEDS_MANUAL`、`PARTIAL`、`DEFERRED`、`UNSUPPORTED_BY_DESIGN`、`OS_DEPENDENT`。禁止模糊的“完成 95%”。

菜单至少覆盖：顶部命令栏、全部下拉及子菜单、文件右键、文件夹右键、多选右键、文件列表空白右键、搜索结果、导航树节点、此电脑与驱动器、标签、地址栏、列头、属性、系统菜单承载、键盘 Shift+F10。

**无法穷举的第三方 Shell 扩展，用“动态发现 + 执行与隔离机制 + 代表性软件验证”覆盖，而非把所有应用名称写进台账。** 对动态菜单记录 API 调用和结果以及测试环境。

## 10. 分阶段执行顺序（不要一口气大重构）

**阶段 A｜只读基线与差距审计**
1. 审查所有现有 UI/控制器/测试/产品边界。
2. 在能接触 Explorer 的 Windows 11 实机上按不同位置、文件类型、菜单层级采集参考；不能实际运行时记录“未实机核验”，引用官方设计文档但不伪造截图。
3. 输出 `docs/EXPLORER_UI_SPEC.md`（窗口布局/状态/焦点）、`docs/EXPLORER_MENU_MATRIX.md`（菜单完整矩阵）、`docs/EXPLORER_COMPAT_GAPS.md`（功能缺口及优先级）。
4. 为已实现功能列出具体代码入口、命令路径、关联测试。不要在第一阶段改动业务代码。

**阶段 B｜P0 Explorer 日常行为兼容**
1. 修正标签、导航/地址栏、主文件区焦点/选择、文件打开、重命名、命令栏可用状态。
2. 补齐 New/Sort/View/Show/More 菜单中真正可落地的项目，与右键/快捷键共享唯一命令路径。
3. 对齐普通文件、目录、空白、多选、搜索结果、左树与驱动器的 Blink-owned 右键行为。
4. 加固“显示更多选项”原生系统菜单桥接与第三方扩展隔离。
5. 外部剪贴板、拖放、文件操作的 UI 完成反馈，与已有 coordinator 正确性对齐。

**阶段 C｜P1 完整日常体验**
1. 增加已经有后端能力的视图、列头、排序/分组、持久化选项。
2. 详情/预览/缩略图、文件夹选项、属性窗口、主页/固定入口等逐个补齐；每个功能完成后单独验证。
3. 文件操作进度、冲突、错误、撤销（仅在具备真实安全实现后）和系统状态的用户体验收尾。
4. 完善 UIA、多语言、缩放、高对比度和大型目录响应。

**阶段 D｜P2 非基础 Explorer/远端能力**
1. 图库、回收站浏览、全会话恢复、系统级接管、特殊 Shell Namespace、MTP、更多云盘集成等，依项目范围和收益决定是否实现。
2. SFTP/WebDAV 及扩展 Provider 仍按 Blink 原有 Provider 架构独立推进，不要把本次 UI 审计变成全部重构。
3. 保留适当的 Explorer 桥接/系统跳转，但在 UI 中明确标注哪些位置实际上并非 Blink 原生管理。

每个阶段拆分为**可单独编译、可验证、可回退的小切片**。每个切片必须有“动机/改动范围/被复用代码/风险/测试/手工验收清单”。不要在一个 PR 中同时推翻主导航、索引、文件操作和菜单 Host。

## 11. 强制测试矩阵与完成标准

### 11.1 基础测试
- 文件夹浏览、不同卷切换、快速连续导航、返回/前进、标签切换/关闭、目录监听更新、目录失效恢复。
- 普通文件、目录、快捷方式、exe、zip、图片、无关联文件、多选/混选、隐藏项、只读目录、搜索结果和盘符上完整菜单校验。
- 同盘/跨盘复制移动、目录合并、重名冲突 Replace/Skip/Keep Both/Cancel、取消中途操作、部分完成、回收站失败、磁盘空间不足、删除后恢复 UI 状态。
- 真实 Windows Explorer → Blink 与 Blink → Explorer 剪贴板/拖放互操作；未实现虚拟文件场景明确标记。
- 目录含大量项目时对菜单展开、切换标签、F2、右键、滚动和退出的 UI 线程响应进行量化检查。

### 11.2 手工 UI 验证
- Windows 11 24H2 x64，浅色/深色/高对比度，100%、125%、150%、200% 缩放；若缺真实环境则标记 NOT RUN。
- 多语言 zh-CN / en-US、不同输入法、长文件名、中文/emoji、长路径、UNC 共享、可移动盘插拔、第三方右键扩展（如 Bandizip/7-Zip，如果实际安装）。
- 每个菜单检查：打开正确、子菜单方向、键盘操作、图标、勾选、禁用、焦点返回、Esc 取消、不会卡顿、实际动作正确。
- 属性/冲突/权限/提示对话框检查：默认按钮、危险操作确认、对话框关闭、错误恢复、Alt+F4、窗口最小化和最大化。
- 对照原版 Explorer 的同一窗口/目录/文件状态截屏；提供差异描述，不能声称“像素级一致”除非有同分辨率实测。

### 11.3 自动化与工程验证
- 在 Windows 开发环境分别运行现有 Debug/Release 构建、单元测试、受控 UI 自动化；使用仓库真实构建命令，先检查环境是否已具备，不盲目安装。
- 中英资源键覆盖、无重复 accelerator 触发、菜单 command ID 唯一、主窗口关闭后后台回调不触发 UI、没有第三方 DLL 注入主 UI、不会出现静默的破坏性 fallback。
- 对所有新增加的可见菜单项提供至少一个单元/集成/手工测试编号；无法自动化的列明原因与手工验证步骤。
- 测试失败时修复原因，不通过删除测试、放宽断言或隐藏菜单掩盖问题。
- 不得将自己没有实际执行的测试写成 PASS；不支持的系统版本不冒充兼容。

**P0 完成门槛**：常见文件管理场景的布局、焦点、键盘、选择、导航、菜单、剪贴板、拖放、文件操作状态具有 Explorer 可理解的一致行为；无不可用装饰按钮、无误导的成功提示、无明显 UI 线程卡死；已实现功能的关键自动化测试通过，剩余项目有明确台账。

## 13. 明确禁止事项

- 禁止只凭想象生成 Windows UI 后宣称“100% 复刻 Explorer”。
- 禁止为视觉完整性加入没有事件和实际动作的菜单、按钮、快捷键。
- 禁止把所有右键菜单固定成一套，不区分文件/文件夹/背景/多选/搜索/设备/虚拟位置。
- 禁止把第三方扩展直接载入 Blink 主 UI，或绕过已有的 ShellMenuHost 安全边界。
- 禁止为 UI 需求改写索引模型或统一文件操作入口，破坏已验证的数据正确性。
- 禁止默认提权、擅自修改 Windows 默认关联/注册表、擅自格式化或删除真实用户文件。
- 禁止一次性实现上百项功能而没有阶段验收；先完整列清单，再按风险与价值分阶段落实。
