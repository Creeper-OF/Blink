# Blink 文件管理器功能范围

2026-11-05用户明确：以文件管理器本身的功能和使用效率为中心，不增加没有实际用途的防护机制。此说明补充既有PHASE1_PLAN与D-0027，阶段范围不因此扩大。

## 日常文件管理

- 浏览本地目录、驱动器和常用位置，支持多标签、地址栏、前进后退、上级目录和刷新。
- 详细信息、列表、网格视图，名称/类型/大小/修改时间排序，文件选择、隐藏项目和目录自动更新。
- 本地索引搜索、当前目录/已索引卷范围、结果打开与定位；索引服务不可用时仍可浏览和操作本地文件。
- 新建文件夹、重命名、复制、剪切粘贴、同卷和跨卷移动，支持文件与目录、多项操作、进度、取消及可理解的错误反馈。
- 同名项的跳过、保留两者、取消、改名，以及后续完成目录合并和覆盖替换。
- 系统回收站删除、确认后的永久删除，拖放、属性和Windows文件剪贴板互操作。

以上条目是完整开发目标，具体已实现/待开发状态以PROGRESS.md为准；列入范围不代表已经完成。

## 后续远端存储

在当前本地文件管理闭环完成后，继续既有SFTP及自建网盘/远端Provider规划，提供连接、浏览和传输能力。优先在Blink内部完成统一文件管理体验；独立的RaiDrive式系统挂载工具不属于当前开发主线。远端能力不提前塞入当前冻结的Phase1交付范围。

## 实现取舍

操作必须作用于用户选中的项目，同名处理不能静默覆盖，复制失败时保留来源，取消和部分完成需要如实显示。这些属于文件操作正确性，采用满足实际需求的简明实现。

工程工作围绕可用功能、响应速度、错误反馈和必要回归展开。独立API探针仅用于确定实际行为，不自动转化为新的产品机制；当前跨卷移动复用既有复制流程与普通文件操作API，不引入事务文件系统或额外防护平台。

人工UI、真实剪贴板和真实服务验收依用户此前要求暂缓；开发由主模型协调独立模块子代理，构建并发1，继续保持WSL稳定。


## Explorer UI与日常交互对齐

2026-11-08用户提供完整UI任务书，按[只读审计与差距台账](EXPLORER_COMPAT_GAPS.md)分阶段落实。菜单只显示有真实命令的能力，系统动态菜单继续由进程外ShellMenuHost获取，不假定每台Windows菜单相同；导航、标签、选择及文件操作仍复用既有权威模型。先审计，再做一个可编译/验证/回退的P0切片，首轮为已有三视图和Hidden的查看/显示菜单。其余命令栏、地址栏、预览、特殊Namespace与远端按各自阶段推进，不借UI规范扩大当前全部交付范围。
