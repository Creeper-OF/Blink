# Blink 文件管理器

Blink 是一个使用 C++20、C++/WinRT 和 WinUI 3 开发的 Windows 文件管理器，目前仍在开发中。

> 这个项目从 7 月份就开始用 AI 做了，中间因为上学停了一段时间。最近发现 B 站已经有人做出了成品，我开始怀疑到底要不要继续做这个东西，心里很矛盾。

## 当前开发与审计

当前优先级为功能实现、响应效率和易用性，体积优化后置。同批功能集中实现、统一构建、逐功能验证，沿用自有文件身份模型和唯一文件操作队列。规则见[AGENTS.md](AGENTS.md)、[维护规则](docs/WORKSPACE_MAINTENANCE.md)及[验证指南](docs/VALIDATION_GUIDE.md)。

本批已实现Clipboard本机结果生命周期和普通三视图/搜索剪切淡化，覆盖单DirectoryCopy、真实部分结果、冲突续接与取消。只新发布扫描已有投影，完成/替换只更新原淡化行；不重枚举或重查。开发环境默认程序已更新原生验证版，并只读核对原标签和选中位置恢复。外部STA/OLE原对象与Explorer完成回传仍待接通；详见[剪贴板交接](docs/CLIPBOARD_TRANSFER_HANDOFF.md)。这是源码同步，没有发布GitHub安装包。

Release独立剪贴板64 PASS/0 FAIL/0 SKIP，完整Phase1为1808 PASS/0 FAIL/4既有权限SKIP，64已包含在完整组。View窗口因未取得前台SKIP；当前Clipboard含无法完整恢复的OLE格式，在任何写入前SKIP。实际透明度、Explorer双向传输和完整环境矩阵仍未验，不把模型或启动检查当实机通过。Debug本批未重建。

先前G06c新建7/改名8/ShiftDelete5为旧版本独立通过记录；A01–A04搜索修正与正式服务更新见[搜索验证](docs/SEARCH_RESPONSE_VALIDATION.md)。本批正式服务/索引库未改。真实搜索首屏和Everything同机基准仍待做。[审计](docs/DEVELOPMENT_AUDIT.md)与下方待办保持这些边界。

## 已实现

- Clipboard本机结果跟踪与剪切淡化已接入：按父身份/FileID/实际名称区分硬链接和替换文件，完整/部分/取消如实处理；真实显示及外部完成通知待验。
- 导航目录目标菜单接入剪切、复制、粘贴，复用原目录复制/移动队列；F5和目录操作完成后按需更新已加载侧栏分支，保留未变节点和展开状态。
- 侧栏目录、常用位置及此电脑驱动器提供目标右键菜单：打开、新标签、路径复制与系统属性；树节点可展开/折叠，虚拟此电脑只显示适用动作。
- F3、Ctrl+F/Ctrl+E聚焦搜索并全选；F6/Shift+F6在文件区、地址、搜索、命令、导航和标签间正反切换，保留草稿与选择。 高级搜索输入仍保留Ctrl+F/E搜索入口。
- 地址栏保留逐级目录菜单、已提交历史和原生收缩；输入路径可列目录候选，方向键选择、Tab补全，选中后Enter或点击进入，Esc恢复原地址。

- 本地目录与驱动器浏览，多标签、地址栏、前进后退、上级目录及目录变化自动刷新。
- 原生面包屑与长路径收缩、Ctrl+L/Alt+D地址编辑、Enter/Esc导航与回焦、F4真实已提交历史；自动刷新保留输入，切换标签取消未提交草稿。
- 详细信息、列表、网格视图，以及名称、类型、大小和修改时间排序。
- NTFS 的 MFT / USN 索引与多盘搜索；搜索范围跟随当前位置，也能在高级选项中指定盘符、目录和子目录范围。
- 文件与文件夹的新建、重命名、复制、剪切粘贴、同盘和跨盘移动，进度、取消及同名冲突处理。
- F2重命名默认选中文件主名并保留最后扩展名，目录和新建名称保持全选；取消后恢复命令能力和文件列表焦点，Ctrl+A仍可修改全名。 改名成功后自动选中新名称并滚动到该项。
- 普通文件覆盖替换、目录复制与移动合并、回收站删除、确认后的永久删除、拖放及属性统计。
- 普通目录与搜索结果统一的 Blink 风格右键菜单：打开、复制、剪切、粘贴、路径复制、重命名、删除和属性；搜索结果支持定位到所在目录。
- 通过“压缩与更多系统选项…”调用 Windows 完整菜单，兼容 Bandizip 等已安装扩展，支持普通目录多选。
- 顶部标准命令栏提供新建、剪切、复制、粘贴、重命名、删除、排序和查看；更多菜单包含选择、属性、刷新与路径复制，窄窗口自动溢出。查看/显示与右键及各标签状态同步，修复隐藏项目开关导致旧标签无法继续搜索的问题。
- Windows 11 风格标题栏、Mica 背景和随系统切换的浅深色外观。

## 从源码构建

工程/API最低目标：**Windows 11 24H2 x64**；本轮实际开发验证主机为**Windows 11 25H2 x64**、MSVC v143、Windows SDK `10.0.26100.0`。Windows App SDK `2.3.1` 与 C++/WinRT `2.0.250303.1` 通过 NuGet 还原，具体依赖以工程文件为准。

在 Windows PowerShell 中进入仓库目录：

```powershell
.\build.ps1 -Configuration Debug -MaxCpuCount 1
.\build.ps1 -Configuration Release -MaxCpuCount 1
```

构建入口会查找已安装的 Visual Studio C++ Build Tools。运行主程序：

```powershell
& .\src\Blink\x64\Release\Blink.exe
```

本仓库当前提供开发版源码，尚无正式安装包。索引服务需要在索引状态入口中单独启用；服务不可用时本地目录浏览仍可使用。源代码本身不会安装或启动服务。

## 验证记录

当前Release通过独立Presentation64项及完整1808/0/4，255原生输入、两语言各390资源键一致。单并发构建259.784秒；Debug未重建。原生组不操作真实Clipboard，不能代替透明度或Explorer互操作。

窗口尝试分别保留：服务器中断0项；未记录前台的菜单检查0 PASS/1 FAIL；补工具前台证据后因无法取得前台0 PASS/0 FAIL/1 SKIP。三个自有进程均正常exit0，七个自有文件和路径/属性核对后清理，每次1015字节。产品没有因为只修测试脚本重新编译。

开发环境默认运行包295文件逐项SHA核对，原用户窗口正常退出，新窗口原标签/选中序号/地址只读核验恢复。这是部署和启动证据，View15与实际Cut显示仍未通过；先前G06c的7/8/5不作为本批新源码GUI结果。完整事实见[剪贴板交接](docs/CLIPBOARD_TRANSFER_HANDOFF.md)。

已清理确认重复产物213191544字节（文件长度累计，非净磁盘变化），源码恢复包只留最新两份；实际Clipboard/Opacity/View待验期间保留一个旧默认变化文件恢复点。当前程序、有效缓存/15包、正式索引与用户配置保留。构建、索引库、原始报告和私有Git历史不上传。
