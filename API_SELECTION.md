# Blink Windows API Selection

## 2026-10-13 Phase 1B Slice 4 file activation

- Background validation reuses CreateFile3 / FileIdInfo / FileStandardInfo through the existing Core metadata boundary and compares the complete FileIdentity at the current link path.
- System association dispatch uses `ShellExecuteExW` with the `open` verb, `SEE_MASK_NOASYNC | SEE_MASK_FLAG_NO_UI`, STA COM and retained Windows security/zone prompts. Microsoft documents that this API can delegate to Shell extensions and COM verb handlers, so it runs only in the ordinary-user `Blink.FileActivationHost.exe` isolation process.
- The helper first queries the current user's `ASSOCSTR_PROGID` using `AssocQueryStringW` with `ASSOCF_INIT_IGNOREUNKNOWN | ASSOCF_NOFIXUPS`. A missing association is reported before dispatch; this prevents the generic Unknown/Open With route from holding a no-association request until the helper deadline. ProgID lookup also supports associations without an executable command, including packaged apps.
- The parent uses `CreateProcessW` with an absolute helper image path, Windows-quoted private arguments and `CREATE_SUSPENDED | CREATE_NO_WINDOW`. The owned helper can be terminated on cancel/close; its worker wait has a 30-second deadline. No target-process `WaitForInputIdle`, process-lifetime wait, privileged service command, Shell Namespace navigation or `runas` verb is introduced.
- WinRT Launcher is not selected for this desktop adapter: its documented ASTA-thread requirement and executable-file restrictions do not cover the general file-manager association surface. This is an API-scope decision, not a legacy-OS fallback.
- Source/reference/resource checks are distinct from native acceptance. The current Debug build stops at missing MSBuild; no new native/helper/UI PASS is claimed.

Primary references: [ShellExecuteExW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecuteexw), [SHELLEXECUTEINFO flags](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfoa), [AssocQueryStringW](https://learn.microsoft.com/en-us/windows/win32/api/shlwapi/nf-shlwapi-assocquerystringw), [ASSOCF flags](https://learn.microsoft.com/en-us/windows/win32/shell/assocf_str), [ASSOCSTR](https://learn.microsoft.com/en-us/windows/win32/api/shlwapi/ne-shlwapi-assocstr), [Launcher.LaunchFileAsync restrictions](https://learn.microsoft.com/en-us/uwp/api/windows.system.launcher.launchfileasync?view=winrt-26100).

## Navigation-pane wheel input repair

导航栏的外层 `ScrollViewer` 继续拥有唯一的纵向 viewport。内层 ListView / TreeView 模板的纵横滚动均禁用。导航栏通过 UI 线程上的 `SetWindowSubclass` 接收本窗口及子窗口的 `WM_MOUSEWHEEL` / `WM_POINTERWHEEL`，在嵌套 XAML 模板处理输入之前，按屏幕坐标、client 原点和当前 XamlRoot 的 RasterizationScale 判断是否落在导航栏。

仅导航栏内的普通纵向滚轮进入即时 `ChangeView(..., disableAnimation=true)`；Ctrl、水平滚轮及导航栏之外的输入交回原窗口过程。步长遵循 `SPI_GETWHEELSCROLLLINES` 的行数/整页/禁用设置。待完成的目标 offset 累计连续及细分滚轮输入；完成事件只清理已达到的目标，鼠标按下或按键会清理暂存目标。窗口关闭和 HWND 销毁时解除 subclass，回调不持有后台线程或额外导航状态。

依据：[SetWindowSubclass](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/nf-commctrl-setwindowsubclass)、[WM_POINTERWHEEL](https://learn.microsoft.com/en-us/windows/win32/inputmsg/wm-pointerwheel)、[SystemParametersInfoW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-systemparametersinfow)。生产窗口消息回归验证滚动、累计距离和响应观测；系统级模拟输入与实物鼠标验收单独记录，不把消息派发通过视为实物鼠标验收。
